# Vertical and horizontal datums

Every height in this project is converted to one reference before it is compared with another. This file records the full chain. Each entry gives what the product's own documentation says, the source we read, and what could not be established from it. Offsets that the documentation does not fix are estimated empirically, with uncertainty, and logged here and in `results/metrics.json`.

**Working datum (D-070, PREREG Amendment 11):** the DAHITI reference, i.e. normal heights in metres above the EIGEN-6C4 quasi-geoid as DGFI computes them (D-074). Level bins, waterlines, the waterline DEM, the hindcast and the validation all live on it.

**Reporting datum:** the Baltic Height System 1977 (BHS-77, normal heights; the system in which Caspian levels are conventionally quoted). H_BHS-77 = H_DAHITI + δ, with δ estimated from the CASPCOM post levels (D-093; section "DAHITI → BHS-77 offset" below). δ is a constant, so it cancels in every hindcast and validation metric (D-070, D-074); it is used only to quote levels.

Horizontal coordinates are WGS84. Areas and grids use the equal-area projection in D-002 of `docs/DECISIONS.md`.

## Chain

```
h_ell (ellipsoidal, satellite) ──(− N of a geoid / quasi-geoid model)──► H above that model
H_model ──(+ N_model − N_EIGEN-6C4, per cell, or + an empirical constant)──► H_DAHITI   (working datum)
H_DAHITI ──(+ δ)──► H_BHS-77                                                            (reporting only)
```

From each height source to the working datum and to BHS-77:

1. **DAHITI levels** (target 39): on the working datum by definition (D-070). Scene levels, level bins, waterlines, the DEM and emergence dates use them directly.
2. **Hydroweb levels** (gap fill and cross-check): GGM02C-referenced; shifted onto the working datum by the ±2-year moving median of the DAHITI − Hydroweb pair differences (D-036).
3. **ICESat-2 ATL06 and ATL08:** H = h_ell − N(EIGEN-6C4), with N interpolated bilinearly from the ICGEM tide-free grid; then the training-block constant c (median of DEM − H) absorbs the remaining constants (zero-degree term, frame and tide-system offsets) (D-069, D-078; `h2.atl06.datum_constant_m`, `h2.atl08.datum_constant_m`). Both inputs are tide-free, so no tide conversion is applied (D-073, D-074).
4. **GEDI L2A and GLO-30:** as stated in their rows below.
5. **Relief grids** (GEBCO_2026, GEBCO_2022, ETOPO 2022, SRTM15+ V2.7, ETOPO1): read as heights above EGM2008 (documented for ETOPO 2022; an assumption for the others) and converted per cell as H_DAHITI = H_product + dN, with dN = N(EGM2008, NGA/PROJ realisation) − N(EIGEN-6C4) (`geoid_correction_primary.npz`) for the total error, and dN without NGA's constant (`geoid_correction_no_constant.npz`) as the sensitivity (D-070, D-074). The shape variant adds each grid's own constant on top (D-072), so it does not depend on either.
6. **SWOT WSE:** not converted. The setup model uses each block's departures from its own mean, so the SWOT geoid's offset from the working datum cancels within a block (D-065, D-066).
7. **CASPCOM post levels (Baltic system):** H_DAHITI = H_BHS − δ. They are used only to estimate δ (D-093).
8. **Reporting:** any level quoted in BHS-77 is H_DAHITI + δ, with δ = `datum.bhs.delta_m` and its σ (`datum.bhs.sigma_posts_years_m` for a basin-wide level; D-093). Products and hindcast results are never shifted by δ.

## DAHITI

- **Source:** Database for Hydrological Time Series of Inland Waters (DAHITI), DGFI-TUM, https://dahiti.dgfi.tum.de; method in Schwatke, Dettmering, Bosch & Seitz (2015), *Hydrology and Earth System Sciences* 19, 4345–4364, doi:10.5194/hess-19-4345-2015. Product page "Water level from altimetry" read on 2026-10-20.
- **Units:** metres (ASCII header: "column 2: water level from altimetry [m]", "column 3: error [m]"; NetCDF attribute `unit = "m"`).
- **Vertical reference:** normal heights. Schwatke et al. (2015, §2): "We compute normal heights by subtracting a (quasi-)geoid model (N) from the ellipsoidal heights. For this purpose, the EIGEN-6c3stat (Förste et al., 2012) model is used, which supplements the EGM2008 geoid model with additional GOCE gravity data." The current product page (data version v6.0) lists the geoid model as EIGEN-6C4 (Förste et al., 2014). Because the geoid model is subtracted from the ellipsoidal height on the same ellipsoid, the resulting normal heights do not depend on which ellipsoid the altimetry was processed on.
- **Relation to BHS-77:** DAHITI heights are physical heights, but they are not tied to the Kronstadt zero. The offset δ = H_BHS-77 − H_DAHITI is estimated from the CASPCOM post levels (D-093; next section).
- **Caveat stated by the producers:** for large lakes a uniform surface is assumed and wind-driven level differences are neglected (Schwatke et al. 2015, §4.3.4). On the North Caspian this matters (wind setup); see brief §8 A5.
- **File in use:** `dahiti_39_caspian_sea_water_level.csv`.
  - Target: DAHITI 39 "Caspian Sea", type Lake; target coordinate 50.4493 E, 41.8041 N, which is in the **Middle/South Caspian**, not the North Caspian.
  - Download: API v2 `download-water-level`, format csv, 2026-10-20T10:54:16Z; sha256 `85b041135a9c4ffd4d46a14df32694d9a2b4d70ba2a5ff5d4d9d7d462f2ad4b3` (`results/provenance/dahiti_39.json`).
  - Columns: `datetime;wse;wse_u` (water-surface elevation and its uncertainty, m).
  - Records: 862, from 1992-09-28 to 2026-09-14. Range −28.909 m (2026-01-29) to −25.672 m (1995-07-06) on the DAHITI reference (`results/qc/dahiti_summary.json`). These are single records. The 3-record running median, which sets the end of epoch E1 (D-037) and the record-maximum and present levels of the sector-layout check (`results/study_area/sector_edges.json`), spans −28.87 m (2025-12-30) to −25.816 m (1995-07-16) (`results/levels/scene_levels_summary.json`, `dahiti_smoothed_extremes`).
  - Software version: the target page lists 8.0 for the water-level series. The product page's processing table describes v6.0 (geoid EIGEN-6C4). The geoid model used by v8.0 is not stated on the pages read, so it is treated as an EIGEN-6C-family quasi-geoid, and the DAHITI→BHS offset is estimated empirically either way.
- **Uncertainty column:** `wse_u` is 0.000 m for 550 of 862 records and at most 0.003 m for 819 of them (95th percentile 0.003 m, 99th 0.008 m, maximum 0.031 m). *(Corrected 2026-10-20: an earlier version said "0.000–0.003 m for every record", which was wrong.)* That is a formal filter uncertainty, not a realistic level error. Phase A estimates the level uncertainty empirically: from the series' own short-term scatter and from cross-checks against independent altimetry (D-018). *(Updated 2026-10-20: the D-018 two-step method is superseded by D-035, which estimates the record noise σ and the bridge rate q jointly; σ = `levels.dahiti_noise_floor_m` in `results/metrics.json`.)*
- **Sampling:** about 10-day sampling (Jason/Sentinel-6 repeat) until 2021. In **2022–2025 it thins to 8–15 records per year, with gaps of up to 129 days** (`scripts/p0_dahiti_qc.py`; gap table in STATUS). Scenes in those years need a supplementary level source (D-018).

## DAHITI → BHS-77 offset (D-093)

- **Source:** the CASPCOM General Catalogue of the Caspian Sea level, monthly post levels in the Baltic system (table row above; `refs/notes/caspcom2026.md`). Script `scripts/a7_dahiti_bhs_offset.py` (`make results/levels/dahiti_bhs_offset.json`); core functions in `src/caspian/gauges.py`, tested in `tests/test_gauges.py`. Output `results/levels/dahiti_bhs_offset.json`, annual differences in `results/levels/dahiti_bhs_annual_diffs.csv`, metric keys `datum.bhs.*`.
- **Method, fixed before δ was computed:** posts = the seven CASPCOM century posts. A post's annual mean is the mean of its 12 monthly means (complete years only). DAHITI is averaged the same way: its daily linear interpolant (days in gaps of at most 60 days between records) gives calendar-month means, and complete months give annual means. d[post, year] = H_post − H_DAHITI; m[post] = mean over the overlap years (posts with at least 10 years); δ = mean of m over the posts. σ: moving-block bootstrap over calendar years (3-year blocks, 10,000 replicates, seed 0), all posts sharing the drawn years.
- **Result:** δ = −0.573 m (`datum.bhs.delta_m`), year-block σ = 0.008 m (`datum.bhs.sigma_years_m`; 95% interval −0.587 to −0.555 m), from 7 posts, 26 years (1993–2021) and 169 post-years. 1999, 2000, 2020 and 2022–2025 drop out because DAHITI gaps longer than 60 days (up to 129 days in 2022–2025) leave them without 12 complete months, and the archive read ends in 2024. So **H_BHS-77 = H_DAHITI − 0.57 m.**
- **The posts disagree more than the years do.** Per-post offsets: Baku −0.423, Neft Dashlary −0.375, Makhachkala −0.500, Fort-Shevchenko −0.597, Guvlymayak −0.748, Turkmenbashi −0.715, Kara-Bogaz-Gol (Duzlybogaz) −0.654 m; between-post SD 0.144 m (`datum.bhs.between_post_sd_m`). Resampling posts as well as years gives σ = 0.052 m (`datum.bhs.sigma_posts_years_m`; 95% interval −0.672 to −0.468 m). **A basin-wide level quoted in BHS-77 carries this σ (0.05 m), not the year-block σ**, because the year-block σ treats the seven posts as fixed (D-093). The spread can come from the sea surface not being level with respect to the quasi-geoid (wind setup and dynamic topography), from levelling errors of the post zeros, and from vertical land motion: the year trend of d is +0.07 to +0.18 m per decade at the four Absheron posts (Baku, Neft Dashlary, Jiloy, Sumgait), against a common trend of +0.013 m per decade (`datum.bhs.drift_m_per_decade`), which would fit subsidence there. None of these is separated here.
- **Sensitivities** (`sensitivities` in the result file; never chosen among): median −0.565 m; 1- and 5-year blocks σ 0.006 and 0.009 m; Bekdash instead of Duzlybogaz −0.564 m; six posts without Kara-Bogaz-Gol −0.559 m; the four posts of Bulletin 20 −0.558 m; monthly instead of annual differences −0.579 m (33 years, 1992–2024); DAHITI with no gap limit −0.580 m (32 years). Range `datum.bhs.sens_min_m` to `datum.bhs.sens_max_m`. The four **North Caspian posts** (Peshnoy −0.637, Tyuleniy −0.576, Lagan −0.340, Kulaly −0.583 m) give −0.534 m (`datum.bhs.north_delta_m`); they are shallow-water posts with wind setup and are not in the primary set.
- **Against CASPCOM's printed sea-mean levels** (typed from the bulletins, `refs/caspcom_bulletin_levels.csv`): the bulletin sea mean minus DAHITI is −0.626 m over the 4 years with a complete DAHITI year (2015, 2018, 2019, 2021; SD 0.027 m; `datum.bhs.bulletin_delta_m`), and −0.639 m over 6 years without the DAHITI gap limit. That is 0.05–0.07 m more negative than δ, within the posts-and-years σ; it follows from the −0.05 to +0.11 m difference between the catalogue and the bulletins noted in the table row.
- **Consistency with the literature:** Ginzburg et al. (2025; Tier B, abstract) correct altimetry downward by about 0.5 m to instrumental levels (`lit.ginzburg2025.altimetry_offset_m`); their altimetry product is not named in the abstract, so this is a check of sign and size only.
- **Use:** only to quote levels in BHS-77. Every hindcast and validation metric is on the working datum, where δ cancels (D-070, D-074).

## GEBCO (2026 and 2022 grids)

- **Source:** GEBCO_2026 Grid documentation (CEDA, `GEBCO_Grid_docmentation.pdf`, read 2026-10-20), §4 "GEBCO Grid, Vertical and horizontal datum":
  - "The GEBCO grid can be assumed to be relative to WGS84."
  - "GEBCO's global elevation models are generated by the assimilation of heterogeneous data types, assuming all of them to be referred to Mean Sea Level. However, in some shallow water areas, the grid includes data from sources having a vertical datum other than mean sea level."
- **Units:** metres; pixel-centre registered, on a 15 arc-second grid.
- **Type Identifier (§3, Table 2):** "70 Pre-generated grid - depth value is taken from a pre-generated grid that is based on mixed source data types, e.g. single beam, multibeam, interpolation etc."
  - In the domain, the North Caspian sea area is coded 70.
  - Sub-sea-level land is coded 40, which suggests a labelling convention for land below 0 m (see `outputs/qc/gebco_2026_tid.png`, written by `figures/qc_gebco_tid.py`, `make qc-figures`).
  - GEBCO_2022 has the same four codes in the domain (0, 40, 44, 70; `results/provenance/gebco_2022.json`), and its documentation repeats the §4 datum statements above in its §6 (`refs/notes/gebco2022.md`).
- **Implication:** the vertical reference of the Caspian pre-generated grid (chart datum, the Baltic Height System, or a level-referenced depth) is not documented. It is estimated empirically, and hindcast errors are reported both as total error and as shape error (PREREG §5).
